# Настройка «Умных ссылок»: руководство администратора портала

> Last reviewed: 2026-07-29

Это инструкция для администратора Bitrix24, который ставит и настраивает приложение. Она
описывает **порядок действий и что означает каждая настройка**, а не устройство кода — устройство
в [`PROCESS.md`](PROCESS.md).

⚠ **Что здесь проверено, а что нет.** Значения REST-полей и поведение поиска сверены с живым
порталом (`pnpm b24:smoke`). Сама последовательность установки на живом портале Маркета **ещё не
прогонялась** — это отдельная задача владельца. Если шаг разошёлся с реальностью, верьте порталу и
сообщите об этом.

## Что делает приложение

Приложение добавляет в портал новый **тип пользовательского поля** — «Умная ссылка». Поле такого
типа рисуется прямо в карточке (например, Сделки) и связывает её с другой записью: записью CRM или
элементом Списка. Из карточки можно найти нужную запись, привязать её, открыть и отвязать.

Связь физически хранится **в отдельном поле-приёмнике**: приложение пишет туда номер связанной
записи. Поэтому полей нужно два — одно показывает, второе хранит.

## Порядок настройки

### Шаг 1. Установить приложение

Поставьте приложение из Маркета. На последнем шаге мастера оно само регистрирует тип поля
«Умная ссылка» в портале. Отдельно ничего регистрировать не нужно.

Если мастер прервался, откройте страницу установки приложения ещё раз — шаг регистрации
идемпотентный, повтор ничего не сломает.

### Шаг 2. Создать поле-приёмник

Это обычное пользовательское поле, в котором будет лежать номер связанной записи.

1. **Настройки → Настройки CRM → Настройки форм и отчётов → Пользовательские поля**.
2. Выберите сущность (например, Сделка) и создайте поле типа **Число**.
3. Запомните его код — он выглядит как `UF_CRM_XXXXXXXXX`. Код понадобится на шаге 4.

Поле-приёмник можно спрятать из формы карточки: сотруднику оно не нужно, работать он будет с
«Умной ссылкой».

### Шаг 3. Создать поле «Умная ссылка»

Там же создайте второе поле, выбрав тип **Умная ссылка**. Именно оно появится в карточке и будет
работать: поиск, привязка, открытие, отвязка.

### Шаг 4. Настроить поле

Откройте любую карточку, где появилось новое поле, и нажмите **«Настроить поле»** (кнопка видна
только администратору). Откроется слайдер настроек.

| Настройка | Что указать |
|---|---|
| **Куда записывать связь** | Код поля-приёмника из шага 2 (`UF_CRM_XXXXXXXXX`). Без него связь некуда сохранять. |
| **С чем связываем** | «Запись CRM» или «Элемент Списка». |
| **Раздел, где лежит список** | Только для Списка. См. ниже — на этом чаще всего спотыкаются. |
| **Номер типа записи** | Для CRM — номер типа (Сделка = 2). Для Списка — номер самого Списка. |
| **Поле компании / контакта в связанной записи** | Необязательно. Нужно, только если включаете отбор по компании или контакту. |
| **Показывать только записи компании / контакта из карточки** | Сузит список кандидатов до записей той же компании (или контакта), что и в открытой карточке. |
| **Дополнительный отбор** | Необязательно. Пары «поле — значение», чтобы убрать из подбора лишнее (например, архивные). |

Сохраните. Изменения долетают до **уже открытых** карточек сами — перезагружать их не нужно.

### Шаг 5. Проверить

Откройте карточку, найдите запись через поиск, привяжите её, откройте по ссылке и отвяжите. Если
что-то не сработало — см. «Если не получается».

## Раздел, где лежит список

Bitrix24 хранит списки в разных разделах портала, и **это не одно и то же**:

| Вариант в настройке | Где это в портале |
|---|---|
| Списки компании | Общие списки портала |
| Процессы (Автоматизация) | Списки, созданные в разделе автоматизации |
| Списки рабочей группы | Списки внутри рабочей группы |

Выбрать нужно тот раздел, в котором список открывается у вас в портале. **Если ошибиться, поиск
вернёт ошибку, а не пустой список** — то есть поле будет выглядеть сломанным, хотя дело только в
этой настройке. Проверено на живом портале: один и тот же портал держал ноль списков в разделе
«Списки компании» и пять — в «Процессах».

Если не уверены — откройте список в портале и посмотрите, из какого раздела вы в него попали.

## Ограничения, о которых лучше знать заранее

- **Из целей CRM поддерживается только Сделка.** Другие типы записей требуют доработки
  приложения — настройка их пока не предлагает.
- **В режиме редактирования карточки поле не работает.** Пока карточка открыта на редактирование,
  связь менять нельзя; поле само об этом скажет. Сохраните карточку — в режиме просмотра всё
  заработает.
- **Элемент Списка открывается в новой вкладке**, а не в слайдере портала. Если браузер блокирует
  всплывающие окна, разрешите их для портала.
- **Права.** Приложение показывает сотруднику ровно те записи, которые он и так вправе видеть:
  оно ходит в портал от его имени. Если запись «пропала» из подбора — скорее всего, дело в правах,
  а не в приложении.

## Если не получается

| Что видно | Что это значит | Что сделать |
|---|---|---|
| «Поле ещё не настроено» | Для этого поля нет настроек. | Нажмите «Настроить поле» и заполните форму (шаг 4). Не администратору — обратиться к администратору портала. |
| «Здесь поле не работает» | Карточка открыта на редактирование. | Сохраните карточку. |
| Ошибка про тип информационного блока | Выбран не тот раздел списка. | Исправьте «Раздел, где лежит список» (см. выше). |
| «Портал не ответил на запрос списка» | Запрос к порталу не прошёл. | Повторите; если повторяется — обновите страницу карточки. |
| «Связанная запись удалена или закрыта правами доступа» | Номер в поле-приёмнике есть, а записи по нему нет. | Отвяжите и привяжите заново. |
| Список кандидатов пуст, хотя записи есть | Слишком узкий отбор. | Проверьте «Дополнительный отбор» и галочки отбора по компании/контакту. |

## Как это выглядит для сотрудника

Сотруднику настройки не видны. В карточке он видит либо строку подбора (поиск, кнопка создания
новой записи), либо готовую ссылку с названием и номером и кнопку «Убрать связь». Всё —
внутри карточки, без перехода в отдельное приложение.
