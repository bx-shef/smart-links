# План живого прогона на портале

> Last reviewed: 2026-07-29

Чек-лист для проверки приложения **на настоящем портале**. Нужен потому, что вебхук
(`pnpm b24:smoke`) работает вне контекста приложения и физически не может проверить главное:
регистрацию типа поля, хранилище настроек, рукопожатие плейсмента и события установки.

**Как пользоваться.** Идти сверху вниз, отмечать `[x]`. Где написано «ожидаем» — это то, что должно
получиться; если получилось другое, записать факт в колонку «что вышло» и не чинить на ходу.

**Что записывать по каждому пункту:** что сделали → что увидели → совпало ли с ожиданием. Скриншот
там, где помечено 📷 (эти же кадры пойдут в карточку Маркета).

| Прогон | Дата | Портал | Кто |
|---|---|---|---|
| | | | |

---

## 0. Перед началом

- [ ] Сборка выкачена и открывается по постоянному адресу (не туннель).
- [ ] `GET /api/health` отвечает 200, флаги готовности видны.
- [ ] В логе старта строка `[boot] db=… oauth=… encryption=… keepalive=…` — записать её.
- [ ] `DATABASE_URL`, `B24_CLIENT_ID/SECRET`, `B24_TOKEN_ENC_KEY` заданы (иначе часть блоков 5–7
      проверить нельзя — так и отметить).
- [ ] Тестовый портал **не тот**, на котором работают живые данные клиента.

---

## 1. Установка

- [ ] Приложение ставится с нуля, мастер доходит до конца без ошибок. 📷
- [ ] Тип поля зарегистрирован: **Настройки → Настройки CRM → Пользовательские поля**, в списке
      типов есть «Умная ссылка».
- [ ] Прерванная установка: закрыть мастер на середине, открыть `/install` ещё раз — **ожидаем**
      повтор без ошибок (шаг регистрации идемпотентный).
- [ ] Переустановка поверх существующей — **ожидаем** отсутствие дублей типа поля.

> ⚠ Самое ценное здесь — понять, доходит ли мастер до шага `event.bind`. Без подписки
> `ONAPPUNINSTALL` **не придёт вовсе**, и блок 7 провалится.

## 2. Настройка поля (цель — CRM)

- [ ] Создано поле-приёмник (тип «Число») и поле «Умная ссылка» на Сделке.
- [ ] В карточке видно новое поле; у администратора есть кнопка «Настроить поле». 📷
- [ ] В настройках **«Куда записывать связь» — это выпадающий список полей карточки**, а не поле
      ввода. **Ожидаем** там своё поле-приёмник.
- [ ] Сохранение работает, слайдер закрывается.
- [ ] Открыть настройки заново — **ожидаем** ранее сохранённые значения.
- [ ] Не-администратор кнопки «Настроить поле» не видит.

## 3. Работа поля в карточке

- [ ] Поиск: ввести часть названия → **ожидаем** список кандидатов. 📷
- [ ] Поиск по номеру записи.
- [ ] Привязка: нажать на название → **ожидаем** ссылку с названием и номером.
- [ ] Открытие: нажать на название связанной записи → **ожидаем** слайдер портала с этой записью.
- [ ] Создание: кнопка создания новой записи → **ожидаем** форму создания; после закрытия список
      обновляется сам.
- [ ] Отвязка → **ожидаем** возврат к подбору.
- [ ] **Высота поля**: карточка со связью не должна иметь под собой пустого места, а подбор не
      должен быть обрезан. 📷 *(проверяем `resizeWindowAuto`)*
- [ ] Режим редактирования карточки → **ожидаем** сообщение «Здесь поле не работает».
- [ ] Поле без настроек → **ожидаем** «Поле ещё не настроено» и кнопку у администратора.

## 4. Цель — Список

Разделов у Списков несколько, и это главный риск. Проверять **каждый доступный**.

- [ ] Обычный список портала (Автоматизация → Списки): поиск, привязка, отвязка.
- [ ] Список из раздела «Процессы» (Лента → Ещё → Процессы): поиск, привязка, отвязка.
- [ ] Список группы/проекта: **ожидаем**, что его нет в выпадающем списке; ввести номер вручную →
      **ожидаем**, что раздел определился сам и поиск работает.
- [ ] Несуществующий номер списка → **ожидаем** сообщение «Список с таким номером не найден».
- [ ] ⚠ **Открытие записи Списка** для каждого раздела: нажать на связанную запись → куда ведёт
      ссылка? **Это то, что сейчас не проверено.** Записать фактический адрес для каждого раздела.

| Раздел | Поиск | Привязка | Открытие ведёт на | Верно? |
|---|---|---|---|---|
| Обычные списки | | | | |
| Процессы | | | | |
| Список группы | | | | |

## 5. Реальное время и права

- [ ] Открыть карточку у сотрудника, изменить настройки у администратора → **ожидаем**, что
      карточка сотрудника подхватит изменения **без перезагрузки**.
- [ ] Сотрудник без прав на целевую запись → **ожидаем**, что она не появляется в подборе.
- [ ] Связанная запись удалена → **ожидаем** «Связанная запись удалена или закрыта правами
      доступа», а не пустоту.

## 6. Мобильный клиент и тёмная тема

- [ ] Открыть карточку в мобильном приложении Bitrix24: поле видно целиком, кнопки достижимы. 📷
- [ ] Подбор и привязка работают с телефона.
- [ ] Открытие связанной записи с телефона.
- [ ] ⚠ **Переключить портал в тёмную тему** и открыть карточку. 📷 Записать: поле выглядит
      светлым прямоугольником в тёмной карточке или нет?
- [ ] Там же в консоли браузера: `getComputedStyle(document.documentElement).colorScheme` внутри
      фрейма плейсмента — **это ответ на вопрос**, пробрасывает ли портал тему во фрейм. Записать
      значение. От него зависит, можно ли вообще делать автотему.

## 7. Установка и удаление (OAuth, серверная часть)

Нужен `DATABASE_URL` и OAuth-креды. Без них блок пропускается — отметить это.

- [ ] После установки в `portal_tokens` появилась строка для этого портала.
- [ ] В логе — исход вебхука установки, **без** идентификатора портала (только `portalHash`).
- [ ] `refresh_token_enc` в базе **не читается глазами** (зашифрован).
- [ ] Удалить приложение с портала → **ожидаем** приход `ONAPPUNINSTALL` и **исчезновение** строки
      из `portal_tokens`. *Это главный пункт всего блока.*
- [ ] После удаления в `portal_tombstone` появилась запись.
- [ ] Поставить приложение снова → **ожидаем** нормальную установку (тумбстоун не мешает).
- [ ] Без `B24_TOKEN_ENC_KEY` установка отвечает 503 и **не** сохраняет токен открытым текстом.

## 8. Попап оценки

- [ ] Задан `NUXT_PUBLIC_B24_MARKET_CODE` → попап появляется. 📷
- [ ] Кнопка открывает страницу приложения в Маркете портала.
- [ ] Повторное открытие в тот же день → **ожидаем**, что попап не показывается снова.
- [ ] Код Маркета не задан → попапа нет вовсе.

## 9. Публичные страницы

- [ ] `/` открывается вне портала, индексируется (есть заголовок и описание). 📷
- [ ] `/privacy` открывается по прямой ссылке, без портала и без JS.
- [ ] В подвале есть ссылки: Маркет, политика конфиденциальности, поддержка.
- [ ] Реквизиты издателя отображаются.
